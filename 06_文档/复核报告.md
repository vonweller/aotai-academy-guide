# 项目问题复核与修复记录

> 分支：`feat/aotai-content-model-qc`
> 范围：CyberCAM 固件、Flask/MQTT 桥、Three.js 网页、内容与音频数据、Blender 场景脚本
> 性质：**离线静态检查 + 本地隔离测试**。未连接真机、未连真实 MQTT broker、未调用语音合成 API、未做部署验收。

## 一、验证方式说明

所有结论来自可复现的本地检查：

| 类别 | 方法 |
|---|---|
| Python | `py_compile` + 隔离实例直接调用（无摄像头/无 MQTT） |
| JavaScript | `node --check` + Node `vm` 全源码加载，替换 DOM/fetch 后直调内部函数 |
| 内容数据 | JSON 解析 + 按 ID 逐字段比对 + 字节级比对 |
| 固件发布内容 | 假 MQTT 客户端截获 `publish()` 全部 payload |
| Blender | headless 重建 + 直接解析导出 GLB 的顶点包围盒 |
| 账本/路由 | Flask `test_client` + 临时 `points.json`（不触碰用户账本） |

## 二、已确认并修复的问题

### 1. 题目在讲解结束前就下发（时序错误）

- **现象**：识别命中后立即广播题卡，9 秒讲解还没播完网页就能作答。
- **修复**：`main.py` 的 `say_relic()` 不再发题；新增 `publish_relic_quiz()`，只在 `relic_phase` 由 `explain` 转入 `answer` 时调用；`answer_relic()` 增加阶段门控。
- **二次缺陷**：计时判断原本位于 `frame is None` / `no hit` 的提前 return 之后，摄像头短暂断流就永远停在 explain。已把计时检查提到检测分支之前。
- **验证**：假时钟 t=110 且 `frame=None` 时进入 answer 且题卡恰好发布 1 次；再次 tick 不重复。

### 2. 标准答案可能随状态外泄

- **修复**：`relic_quiz` 事件只发 `{q, options}`；网页端拒收带 `answer` 字段的题卡，`state.relicQuiz` 只存题干与选项。
- **验证**：截获全部 MQTT payload，`"answer"` 出现 0 次；题目事件键集为 `{q, options}`。
- **边界（重要）**：这只说明答案不经 MQTT 下发，**不等于答案只在设备内**。若将来启用识别，共享的 `content.json` 仍需包含 `quiz.answer` 供网页就绪校验，而站点可直接提供该文件。启用前必须拆分公开/私有题目并做服务端鉴权计分。

### 3. 远程语音可被旧 ID 与外部文案劫持

- **现象**：`aotai/event` 有 ID 白名单，但 `aotai/cmd`、`aotai/k10`、`web/cmd` 走 `handleCmd` 的 `speak` 分支时完全没有校验，旧 `p_all_done`/`p_congrats` 仍可点播；且白名单只校验 ID，不校验文案，外部 `data.text`/`data.lang` 会被直接信任。
- **修复**：新增 `configuredSpeechText()` + `playConfiguredSpeech()`，所有远程入口统一走同一函数：ID 必须在当前内容白名单内，文案必须由当前 `content.json` 重新派生，语言限定 `zh`/`yue`。
- **验证**：Node VM 中四条通道（event / aotai/cmd / aotai/k10 / web/cmd）播放 `p_all_done`、`p_congrats` 均被拦截；有效 ID 配 `text:'INJECTED'` 时实际播的是内容库原文。

### 4. 答错后网页卡死

- **现象**：`relicQuizResult` 无论对错都禁用全部选项；固件答错只是保持可重试，并不重发题卡，于是网页端一次答错就再也点不动。
- **修复**：网页仅在 `ok === true` 时禁用；固件答错分支补发一次无答案题卡。
- **验证**：错答后按钮 `disabled` 全为 `false` 且提示改为「可以重选」；答对后全为 `true`。

### 5. 远程答题可打旧卡片

- **修复**：`on_cmd` 的 `relic_answer` 增加 `key` 与当前 `self.relic_key` 一致性校验。
- **验证**：提交其他候选 key 时无任何状态变化；提交当前 key 才记账。

### 6. 断网兜底文案不完整且含未格式化占位符

- **现象**：固件 fallback 只有 9 条提示，主内容有 18 条；缺失时离线会静默无声。且 `p_relic_next_active_v2` 含 `%d`，但该句是直接 `say()` 播报的，占位符不会被替换。
- **修复**：补齐 fallback 至 18 条，与主内容按 ID 逐字一致；移除该提示中的 `%d`（剩余件数改由字幕单独显示）。
- **验证**：ID 集合完全相等，中/粤文本逐条相等；`smoke_ui` `ALL_UI_OK`。

### 7. 音频清单残留旧三类内容

- **现象**：`manifest.json` 88 条里 82 条是旧类别（香云纱/千角灯/旧完成语），与当前文案不符；`gen_audio.py` 只增不减，孤儿条目永远留着。
- **修复**：清单只保留文本与当前内容完全一致且文件真实存在的 6 条；`gen_audio.py` 合并前按 `(id, lang)` 与当前文案过滤。
- **验证**：清单 6 条与真实 mp3 一一对应；生成器收集到 35 个当前 ID。
- **未完成**：v2 新文案**尚未生成音频**（未调用 API）。网页缺音频时只显示字幕，固件缺音频需 API key。不要宣称已有新语音。

### 8. 网页题目渲染缺少形状防御

- **修复**：`relicQuiz()` 校验题干非空、选项 ≥2 且每项带字符串 `key` 才渲染。

### 9. Blender 屋顶绕序与瓦垄方向

- **现象**：长轴分支屋面绕序朝内；瓦垄原先平行于屋脊，看起来像横条。
- **修复**：两个分支改为一致外向绕序；瓦垄按坡向生成，沿屋脊等距排布。
- **验证**：直接解析导出 GLB，三座屋顶均闭合、三角形外向、无退化；六机位 `behind_camera=0`、`worst_ndc<1`。

### 10. Blender 瓦垄悬空 / 织机布面悬置

- **现象**：复核发现瓦垄与坡面有约 7.5 mm 净缝；织机布片完全悬空（距下侧梁 0.115 m、距卷轴 0.20 m）。
- **修复**：瓦垄偏移改为 0.026（半厚 0.0275），形成 1.5 mm 嵌入；布面高度改为 `bottom_z..top_z` 并与后框上下横梁、侧梁相交，卷布轴移到后框下梁处。
- **验证**：从重建 GLB 取包围盒 —— 布面 `y 0.88..2.085` 正好落在框架 `y 0.58..2.13` 内，深向 `z -11.41..-11.39` 位于框架 `-11.455..-10.345` 内，且布面下缘与卷轴顶 `0.88` 相接。

## 三、未修复、仍属风险的问题（建议后续处理）

### A. 普通积分接口可伪造/重放（高）

`POST /api/add` 无任何身份或来源校验，任何能访问该端口的人都能刷分。识别奖励类已 fail-closed（409），但 `quiz_right`、`stage_clear` 等仍可被直接调用。
**建议**：改为服务端按进度/事件发放；或至少加会话令牌 + 一次性 nonce + 频控。

### B. 设备积分与网页积分是两套账（中）

设备端 `points.py` 写本地文件，网页端写 `02_数据/points.json`，二者无同步、无对齐机制，用户会看到两套分数。
**建议**：明确以哪端为准，另一端只做展示；或加带签名的同步协议。

### C. 公共 MQTT 凭据硬编码，且无消息认证（高）

`config.py` 内公开 broker、账号密码直接写在源码；`aotai/cmd` 任何订阅者都能下发指令。当前已通过前端白名单降低影响面，但本质仍是未认证控制通道。**上线前建议换私有 broker + TLS + 账号隔离**。

具体建议：`MQTT_USER`/`MQTT_PASS` 改环境变量（`AOTAI_MQTT_USER/PASS` 模式已有先例）；`CLIENT_ID` 加随机后缀避免多台同名互踢。

### D. 识别与奖励仍关闭（设计如此，但需明确）

`RELIC_RECOGNITION_ENABLED` / `RELIC_REWARDS_ENABLED` 均为 `False`，现有模型为旧 6 类 schema，被显式拒绝加载；训练脚本在缺少已核验样本时直接抛错拦截。这是**有意设计**，不是缺陷。启用前仍需：权威出处、图像授权、每类完整样本、独立测试集、目标设备部署回归。

E. Blender 场景仍是简模
屋顶坡面中部瓦垄已贴合，但歇山/攒尖端坡仍无瓦垄；场景泛灰、装饰简略；讲堂机位有门框遮挡。受控 GLB/QC 未改动，候选仅在临时目录。
